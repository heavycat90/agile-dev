# agile-dev

轻量级企业迭代开发方法论 — 适用于个人/小团队产品开发的工程方法。

继承 Agile 精神，融合企业级质量门禁与可追溯性，同时保持轻量——每个仪式都有实际价值，不为流程而流程。

## 核心理念

- **五Agent协作**：需求分析 → 规划 → 交付 → QA → PMO，异步并行，队列驱动
- **双轨工作模型**：快速通道（≤2 文件小变更）+ 标准通道（完整规划）+ 需求池
- **5 道质量门禁**：需求确认 → 方案确认 → 计划确认 → 质量确认 → 发布确认
- **角色切换**：单人项目也能从 PO/Dev/QA/Ops/PMO 多视角审视

## 一分钟上手

作为 Claude Code Skill 使用：

**新项目接入**
> "这是新项目，叫 _{项目名}_"

Skill 自动引导完成初始化：`project-basic.md`、目录结构、初始文件。

**功能开发/变更**
> "我想加一个 CSV 导出功能"

Skill 激活需求分析Agent，分析后自动分流——小改动走快速通道直通实施，大变更走标准通道进入版本规划。

**查看项目状态**
> "项目进度怎么样"

PMO Agent 扫描全项目数据源，生成看板。

## 五Agent协作模型

| Agent | 职责 | 产出 |
|-------|------|------|
| 需求分析Agent | 需求澄清、方案设计、分流决策 | 需求条目、ADR |
| 规划Agent | Backlog 选取、Story 拆解、版本划分 | 实施计划、版本路线图 |
| 交付Agent | 代码实施、自审、发布 | 代码变更、Git commit |
| QA Agent | 独立验证、环境管理、质量门禁 | QA 报告、测试用例 |
| PMO Agent | 项目监控、看板生成 | 项目看板 |

## 门禁体系

| 门禁 | 检查项 | 快速通道 | 标准通道 | Hotfix |
|------|--------|:--:|:--:|:--:|
| 1: 需求确认 | 需求澄清、风险识别、验收标准 | 轻量 | 完整 | 事后补充 |
| 2: 方案确认 | 方案设计、影响分析、ADR | ✓ | ✓ | - |
| 3: 计划确认 | Story 拆解、版本划分 | - | ✓ | - |
| 4: 质量确认 | 定向验证、冒烟测试 | ✓ | ✓ | ✓ |
| 5: 发布确认 | 发布记录、change-log | ✓ | ✓ | ✓ |
